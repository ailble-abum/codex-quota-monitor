# V2 消息级用量恢复契约

2026-09-21。此阶段恢复旧版本中属于产品功能的消息级 Token chip 与侧栏用量提示，但不重新引入旧 renderer。

## 数据边界

- `ConversationDetail` 只消费 V2 `SessionJournal` 已读出的 `response_item` 与 `token_count` 记录。
- 只发布助手消息的短文本前缀和经过数值校验的 Token 字段；不发布原始事件、用户正文、环境上下文或文件路径。
- 每个任务最多保留 160 条消息、40 条带用量的助手项；前缀最多 120 个字符。
- 任务身份仍必须通过 `session_meta.id` 核对，详情不能跨任务回退。

## 页面投影

- `panel_host_details.js` 是仓库内自写模块，使用事件委托和现有宿主属性读取消息节点。
- 侧栏只给当前 V2 快照中已核对的任务行添加独立 tooltip 标记；不改宿主标题、内容或选中状态。
- 助手消息只在找到稳定动作行时插入一个自有 Token chip，重复刷新复用并清理过期节点。
- 不创建 `MutationObserver`，不复制旧 `applySidebar`、`applyFooters` 或消息匹配实现；消费者卸载会移除事件委托、tooltip 和 chip。

## 验收边界

当前目录适配器只发布活动任务，因此侧栏提示先覆盖活动任务；多任务侧栏摘要需要后续扩展安全的多摘要数据契约。健康、历史、通知和更新检查仍是独立后续阶段。

Python 单元测试覆盖消息过滤、数字投影、截断、重置与详情隔离；真实 CDP 验收确认当前页面产生 40 条详情项、3 个消息 chip、1 个活动侧栏提示，旧属性保持为零。
