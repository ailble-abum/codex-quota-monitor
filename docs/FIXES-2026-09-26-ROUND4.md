# 2026-09-26 第四轮：悬停压缩数据与边缘交互

本轮对应用户新增反馈：悬停需要压缩次数和压后首请求占比；人物旁小柱过近、面板出现时仍显示；长面板自动隐藏后再次打开没有回到紧凑栏；顶部菜单额度消失。

## 修复范围

- 悬停摘要复用对应日志的压缩统计，只投影该对话需要的字段。不同对话独立取值；缺失或尚未观测的占比不伪造为 0%。
- 人物旁的小柱与人物留出间距；任何面板显示时，包括紧凑栏，都收起小柱，面板隐藏后恢复。提供短过渡，并尊重系统减少动态效果的设置。
- 自动收回长面板后复位到紧凑模式；重新移到边缘时先打开紧凑栏。保留人物锚点以及明确固定面板的操作。
- 顶部菜单服务原本显示运行，但用户看不到；单独重载该菜单服务后，用户明确回复“已经看到了”。此项是真实 macOS 用户确认，没有把进程状态当成可见性证明。

## 顶部菜单诊断

本轮没有修改菜单程序，也没有修改系统菜单栏设置。重载时菜单自身报告 `Codex · 6%`，该数值会随实际使用变化。

Apple 的 [`NSStatusItem.isVisible`](https://developer.apple.com/documentation/appkit/nsstatusitem/isvisible) 文档说明，状态项因空间不足被暂时隐藏时该属性也可能为 true。因此，运行状态或可见属性不能替代用户看到菜单项。本次未确认底层隐藏原因，不把空间不足当成已证实根因；本次恢复由用户直接确认。
