# 2026-09-26 修复清单与验收

基于上游 v2.0.11 和本地适配分支 `codex/local-v2.0.11`。本轮处理用户报告的宠物/面板分离、显示不全、展开收起跳动、侧栏悬停信息错位，以及进入对话后上下文刷新异常。代码检查围绕这些路径展开，不代表对全部功能作出无缺陷保证。

## 界面与新版客户端

| 问题 | 已确认原因 | 修复 |
| --- | --- | --- |
| 宠物缩放后与面板上下分离 | 对使用 CSS transform 缩放的宠物坐标再次除以比例 | 宠物与面板使用同一个视口纵坐标 |
| 右停靠宠物显示不全 | 从左上角放大，右半部超出窗口 | 右停靠以右上角为缩放原点 |
| 展开、收起跳到另一位置或另一边 | 两种模式独立保存旧坐标、旧停靠边，并重复定位 | 切换时继承当前锚点和停靠边，只有尺寸保留各模式设置；去掉重复定位 |
| 调整尺寸后位置不稳 | 宽度动画期间测量到中间尺寸 | 宽度直接生效后测量，保留侧边显示的动效；验证小窗口内部设置可滚动访问 |
| 侧栏悬停文字不对齐 | 用空格拼接中英文标签和数字 | 使用两列网格，标签与右对齐数字分别排版 |
| 悬停内容被裁切、无法读完 | 未限制视口高度；浮层不接收鼠标 | 视口内翻边/夹取，支持换行与滚动；跨间隙保留浮层，持续数据刷新保留阅读位置 |
| 悬停显示失效任务内容 | 未检查浮层所属行是否已失效或进入非活动页面 | 更新时检查归属并清理失效提示，数值变化原位更新 |
| 新版 Codex 当前任务识别失败 | 把缓存的非活动页面中的任务行也计入当前候选 | 按客户端页面标记排除 `data-app-shell-active-page="false"` |

客户端接口核查：本机 `/Applications/ChatGPT.app`，版本 **26.924.22138，build 11645**。只读核对 app.asar 中的页面和侧栏属性约定，没有复制客户端实现或修改应用二进制。这些是当前版本的内部接口证据，不是官方稳定 API 承诺。

## 上下文刷新与读取优化

| 问题 | 已确认原因 | 修复 |
| --- | --- | --- |
| 进入/切回对话后 CTX 显示旧值，再逐步变化 | 切换任务清空增量读取缓存；未读到日志末尾的摘要也会发布 | 保留读取游标；当前日志尚未完整读取或末行未写完时显示加载状态，不把日志中间值当作当前值 |
| 会话较多时当前任务读不到 | 128 个文件的上限原本作用于整个历史目录，超过即整体失败 | Codex rollout 适配器优先读取当前任务的全部同名候选，再补最近的后台日志，总量仍限制为 128；普通目录适配器保留原有完整性限制 |
| 多个同名候选使单轮读取超过预算 | 每个候选独立获得最大额度，没有合计约束 | 同名候选共享全局读取预算，同时保留后台日志的有界读取进度；重复身份继续拒绝选择 |
| 后台日志追加后切回仍重复读取 | 缓存校验错误地使用已推进的新游标 | 按保存的旧位置验证已读前缀，后台已处理的追加内容可直接复用 |
| 复用缓存时可能沿用被覆盖文件的身份 | 原读取器只识别文件替换或缩短 | 切回时验证文件身份、头尾窗口；同大小但修改时间变化保守重读；截断和身份改写重新校验 |
| 命名不一致的日志干扰侧栏摘要 | 只检查内容身份，没有与文件名对应 | Codex 适配器要求文件名与内容身份同时匹配；错误命名文件不进入摘要 |
| 少量合法对话始终识别不到 | UUID 最后一段恰好全是数字时被误当作噪声文件 | 按完整 UUID 结构识别，继续忽略短数字噪声文件 |

合成复现：两个约 3.3 MiB 的对话日志各包含 3,000 次用量事件，最终上下文应为 30%。旧实现交替进入时反复返回 19.03%；修复后先返回加载状态，追到末尾才发布 30%。129 个有效 rollout 文件原本导致整个读取失败，修复后当前任务仍可读取。

完整数据链路另外覆盖：80% → 切入无用量记录的任务并清空旧值 → 首条记录 2.5% → 上下文压缩后清空 → 压缩后的首条记录 3% → 页面重载后保持 3%。当前页面任务切换由已有的 250 毫秒检查识别；本轮没有改成零延迟机制。

保留的资源边界：最多扫描 4,096 个目录项、深度 8、同时保留 128 个日志、Codex 适配器单轮读取总预算 4 MiB。旧任务的侧栏摘要可能不在最近窗口中；进入该任务后会优先加载。初次读取大型历史日志需要若干轮，期间显示加载状态。这不是全历史后台统计或无界缓存。

缓存沿用日志追加写入约定，相同长度的改写保守重读，未进行逐轮全文件哈希；非追加式历史编辑不在本轮完整验收范围内。后台日志仍逐步追尾，其历史摘要可能需要数轮刷新。
