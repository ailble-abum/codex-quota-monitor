# 2026-09-26 第二轮实景问题修复

本轮基于用户安装后的两张截图和实际故障反馈。上一轮的短面板、简短日志测试没有覆盖长历史面板、压缩后零输入记账事件及新版内置 CLI 的实际位置；上一轮通过不等于这些实景问题已解决。

## 问题、根因与修复

| 用户反馈 | 本轮证据 | 修复 |
| --- | --- | --- |
| 账户额度无法识别，剩余额度消失 | 截图明确报“找不到 Codex CLI”；配置仍指向已不存在的 `Contents/Resources/codex`，当前应用 CLI 位于 `codex-cli/CodexCLI.app/Contents/MacOS/codex` | 在显式配置的同一应用包内兼容已知 CLI 布局，每次刷新重新解析，保留外部自定义 CLI 的精确路径 |
| 对话列表悬停没有插件数据 | 本机 65 个日志合计约 1.85 GiB，最大约 423 MiB；原后台每文件每轮 16 KiB，尚未到文件尾的摘要不显示 | 优先读取悬停任务，当前任务选择不变；全局预算剩余量转给悬停和后台日志；读取期间显示明确状态，完成后原位更新数据 |
| 红茶御姐初始姿势/表情不对 | 皮肤资源映射正确，但 `unknown` 额度状态直接映射成 `concerned`；每秒还会重建人物图像节点 | 未知额度保持常态；只有真实低额度等条件才进入提醒表情；相同皮肤和语言刷新时保留图像节点与交互表情 |
| 人物旁额度柱太远、与弹出面板重叠 | 320px 表情画布带透明留白，例如红茶人物联合透明边界从 x=86 开始；原位置按整张画布计算 | 六种皮肤分别使用六帧联合可见边界定位额度柱，表情切换不跳位；面板横向留出人物和额度柱的位置 |
| 展开后人物跳到顶部，收起再展开无法回原位置 | 长面板与人物共用夹取后的顶部坐标，面板被向上挪动时污染了人物保存锚点 | 人物锚点与面板显示位置分开；只挪动长面板并允许内部滚动，展开/收起继承人物原锚点 |
| 压缩后首请求显示 0 | 真实日志中每次 `compacted` 后先出现 input/cached/output=0 的记账记录；随后才有真正请求 | 首请求统计跳过零输入占位与压缩前旧快照，记录真正请求的 input_tokens；缓存输入已包含在输入内，不重复相加 |
