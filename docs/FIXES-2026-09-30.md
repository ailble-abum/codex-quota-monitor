# 2026-09-30：新版对话身份、ChatGPT 切换与额度恢复

## 问题与修复

本机宿主版本为 26.928.20755（Build 12246）。只读诊断确认主页面仍为 `app://-/index.html`，原有 CLI 包装路径解析也能读取额度；本轮没有证据支持“主页面地址已改变”或“账户登录失效”。

新版侧栏的本地对话可能继续使用 `local:client-new-thread:…` 临时标识。旧解析只接受裸 ID / `local:ID`，因而返回未选中，并在账户读取之前退出整个更新周期。修复从当前活动页面唯一的 composer portal 读取已解析 conversation ID，仍要求侧栏行的 kind/host 均为 local；随后继续核对日志内部 session_meta。隐藏页面、多个活动行、多个 composer、未解析别名、不同本地 ID 或 ChatGPT 标识都不能借用本地日志。

账户额度刷新、面板初始化、更新按钮和菜单栏采样现在可以在无本地任务时运行。切到 ChatGPT 聊天会立即清空上一条本地上下文，但新鲜的账户额度保持显示；ChatGPT 页面明确标为“Codex 账户额度”。本轮来源没有提供 ChatGPT 聊天上下文 Token 数，因此显示“ChatGPT 聊天未提供上下文用量”，不按文字长度估算，也不套用本地 Codex 上下文。

额度读取失败后按 5 / 10 / 20 / 40 / 60 秒自动重试，成功后恢复每分钟轮询。失败立即替换旧额度，120 秒新鲜度约束继续有效。等待宿主模式下，临时 socket 断开、超时和协议错误保持有界退避，后续重连无需退出监视器；目标歧义和无效配置仍按原失败预算处理。宿主无法连接时，账户仍会独立轮询并更新菜单栏采样。

另以合成进程复现了只杀 CLI 父进程会留下继承 stdout 的后代；没有复现本机无限 wait，因此不把它认作已证实的掉线根因。POSIX 查询现在使用独立进程组并清理整个查询组，进程退出等待最多 2 秒；只涉及监视器创建的只读 app-server，宿主正在运行的 app-server 不在此组中。
