# 本机 V2 切换

用户已授权从旧版切换至本地 V2 预览版。旧版文件和 LaunchAgent 定义保留供回退，停止其运行后才启用 V2，避免两个监视器共用页面。

生产数据发现：本机会话目录含 573 份日志，通用目录源的 128 文件上限不适用。新增显式配置 `session_layout: "codex-rollout"`，仅为活动任务筛选 `rollout-*-TASK_ID.jsonl` 文件；仍使用有界目录遍历、描述符范围约束、内部 session_meta 身份核对及重复身份拒绝。文件名只是候选定位，不是身份凭据。未匹配到规范命名时显示不可用，不猜测其他文件。原通用目录行为不变。

此模式每轮最多读取 4 MiB 当前任务候选，切换任务重建候选索引。无关旧日志的半行/异常不再阻断当前任务。目录变化仍沿用现有重新索引节流与失效策略。真实当前任务通过 5 轮加载得到已核对身份的摘要，未输出正文。

部署使用 V2 独立目录与 `local.codex-quota-monitor-v2` LaunchAgent。只连接已存在的显式 9222 主窗口，不修改或重启宿主。宿主关闭时由 launchd 节流重试；本版本不负责重新开启调试端口。账户来自显式本机 Codex app-server。

停止旧服务后还需清除其遗留 Update/Payload hook，否则新协议可能误采用旧消费者。只在旧面板已移除时执行，随后以 V2 的消费者摘要、owner、实时快照和真实窗口检查确认切换。

回退：先 bootout V2 服务并释放/等待其页面租期清理，再以 launchctl enable 恢复 gui/501/local.codex-quota-monitor 和 gui/501/local.codex-quota-menu，然后运行原版 monitorctl.py start。不得让两版同时控制同一页面。旧版历史/通知/菜单能力不会由 V2 预览自动替代；正式上传保持未通过状态。

## 本轮验证

Python 3.9.6 / 3.14.3 全套各 132 项通过。新增测试覆盖超过 128 份无关坏日志、切换任务、文件名与内部身份不符、重复匹配拒绝。

首次真实窗口检查确认 consumer ready、摘要与安装文件一致、quota live、活动任务与唯一 summary 身份一致、面板唯一且可见。随后发现紧凑栏把“距离重置”误当成“至少还能使用”：无耗尽速度估算时不能保证额度持续到重置。因此移除这一回退，改为显示已有真实百分比；仅有有效耗尽估算时才展示时间预算。Chromium/WebKit 的聚合显示、挂载控件回归，以及真实账户→隔离深浅主题面板回归通过。

部署目录为 `~/Library/Application Support/CodexQuotaMonitorV2/preview-20260920-switch`。旧监视器和菜单 LaunchAgent 已停用且禁止自动启动；其程序和服务定义保留。V2 已注册并启用常驻服务。修正版重启前一次 SIGTERM 记录 cleanup=released，主页面的 V2 节点、consumer、delivery、snapshot 和 hook 均已清理；随后加载修正后的固定 renderer。

真实原生窗口的主动跨任务切换、刷新恢复未执行；对应隔离测试不提升为原生证据。常驻服务已运行不代表重启宿主后调试端口会自动开启。未上传。
