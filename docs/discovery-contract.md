# 受限会话查找与离线预览

2026-09-20。保留旧版产品设计；仅在独立 V2 增加显式目录查找，没有连接正在使用的监视器。

## 接口与复用选择

```sh
python3 -m quota_monitor /path/to/synthetic-sessions --thread demo --discover
```

普通模式仍接受单个显式文件；--discover 把同一位置参数解释为目录，不读取默认用户目录、认证、数据库或环境配置。

实现复用本项目 SessionJournal、身份契约和数值兼容桥。目录遍历使用 Python 标准库 [os.scandir](https://docs.python.org/3/library/os.html#os.scandir)，支持迭代及不跟随链接的类型检查，足以覆盖当前需求，不引入第三方文件索引库或复制旧 inspector。该文档于本轮核查；合成目录已实测，真实会话规模尚未验收。

## 范围和预算

- 遍历指定根目录下、扩展名为小写 .jsonl 的普通文件；不依赖名称、修改时间、父任务或根会话 ID 选择任务。
- 遇到符号链接与特殊文件时跳过；根目录本身是符号链接时拒绝。硬链接若形成两个匹配路径也视为歧义，不猜测用户意图。
- 默认最多处理 4096 个目录条目（非日志也计数）、8 层子目录、累计读取 16 MiB。每批最多 256 KiB。
- API 的 max_entries/max_bytes 必须是正整数，max_depth 为 0..32；CLI 的 --max-polls 仍为 1..4096，在发现模式换算为整个扫描共享的字节预算，不是每个文件独享预算。
- 无排序或全目录列表缓存，只保留当前文件归约状态、最多一个匹配快照和有限层级的遍历迭代器。不建立持久索引。
- 当前保守实现需要读取范围内日志的完整可见内容。大目录可能很快达到预算；此时应缩小明确指定的目录或增加预算，不把它当作生产级高频扫描器。下一阶段按实际接入需要补增量索引/候选复用。

## 结果

只有所有范围内日志均完整读取、身份明确且恰好一个匹配时返回 ok 和白名单 reading。

- not_found：完整扫描后没有匹配。
- ambiguous：完整扫描后存在多个匹配，不按“最新”猜选。
- incomplete：条目/深度/字节预算不足、日志身份缺失/冲突、坏行、半行、检测到文件重置、候选不可读或子目录错误。不发布此前找到的匹配。
- unavailable：指定根目录不存在、不是目录、是链接或初始不可访问。

上述非 ok 状态在 CLI 中均退出 2，并输出空 summaries；返回值及 CLI 不含文件路径、正文、其他任务 ID。API 另提供 entries/files/bytes_read/invalid_lines 计数；files 表示尝试检查的普通 JSONL 数量，不表示验收成功数。

读取器新增 pending 标志，经 SessionJournal 传递，只表示有未换行片段或正在丢弃超长半行。发现模式据此拒绝把部分文件当完整扫描；原单文件预览的等待半行语义不变。

## 验证和边界

67 项测试在 Python 3.9.6、3.14.3 均通过；包括嵌套查找、错误文件名、别名、重复候选、准确字节上限、总预算共享、深度/条目上限、未知/冲突/坏日志、半行与暂时不可读后恢复、符号链接环、FIFO、根目录不可用，以及真实 CLI 子进程输出。

这不是安全沙箱或文件系统原子快照：根路径的祖先链接、并发路径替换、扫描后新增文件/追加数据及原地修改不保证被检测；在可信、稳定的本机测试目录使用。预算约束处理量，不提供磁盘/网络文件系统 I/O 墙钟超时。尚未验证 Windows 原生行为、真实 Codex 会话规模和 UI 切换。
