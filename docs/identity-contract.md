# 日志身份核对

2026-09-20。本轮仅在独立 V2 实现身份核对，不接入现用安装或自动扫描用户目录。

## 来源与选择

核对 [官方固定版本 protocol.rs](https://github.com/openai/codex/blob/5ee2bdf1e0e04064bc427ae31a49a01e8f7064df/codex-rs/protocol/src/protocol.rs)：SessionMeta.id 是 ThreadId；session_id 是根任务的 ID，forked_from_id、parent_thread_id 也不是当前任务身份。只依据字段接口实现，不复制上游解析代码。复用已有 JournalReader、thread_key 与标准库，无新增依赖。源码接口已核对，真实日志与 UI 尚未验收。

## 行为

- 完整 session_meta 行的 payload.id 作为任务标识，忽略路径、正文、父任务与根会话字段。
- 接受已有 task key 字符集（ASCII 字母、数字、连字符、下划线，1..128），不声称完整校验官方 UUID 类型。日志内不接受 local: 别名，选择参数仍可使用该别名。
- 初始 missing；同一 ID 可重复；无效元数据或不同 ID 变成 conflict，后续追加有效行不能恢复。
- 读取器检测到文件替换或截短时，同时清理统计与身份。末尾半行等待换行；跨读取批次保持身份状态。
- verified 只表示已读取完整、格式受限且目前没有冲突的元数据，不是密码学认证、文件可信证明或整个日志有效性认证。保留读取器对原地修改/截短再增长的既有边界；坏 JSON 行仍按读取器契约跳过并计数，不能识别其原本类型。
- 公共兼容桥同时检查身份、当前任务、读取状态和追赶状态，不能通过伪配字典键发布另一个任务的读数。
- CLI 核对预期任务并输出通用错误状态，不输出其他任务 ID、文件路径或原始元数据。进程内字典不是安全隔离边界。

## 验证与下一步

合成文件与子进程验证：身份缺失、晚到、重复、无效、冲突粘滞、分段读取、文件替换、CLI 不匹配及桥接拒绝。全套 50 项测试在 Python 3.9.6 和 3.14 通过。

本轮完成的是防误关联的数据契约，不是发行替代品。下一步做受限目录发现与重复候选处理，再接入隔离面板；不删除旧归因，也不宣称来源审计已完成。
